## 环境与隔离

实测在 Windows、Node.js 24.18.1、npm 11.16.0、Git 2.55.0 和 Edge 环境进行。Git、Node 和浏览器已安装，本轮实际检查版本并安装应用，不包含重装操作系统或在空白电脑安装这些先决工具。Playwright 仅用于测试自动化，不是程序运行依赖。程序无需先安装 npm 包，也不自带模型账号。

- 每份克隆先记录远端 URL、提交 SHA、跟踪清单和干净状态，确认没有 `.local/`、`.runtime/` 或 `node_modules/`。
- 技能安装使用新的子进程 `HOME`、`USERPROFILE`、`CODEX_HOME`，不覆盖真实用户的技能；首次浏览器存储为空。
- 现有 4680、4681、4682 服务保持运行，用于真实检验端口冲突。测试员不打开旧实例的个人页面，也不停止其他进程。
- 学生背景和回答全部虚构。真实项目仅从各自克隆中的公开研究基线取项目与来源，不复制其中的 profile，不重新推定官方核验日期、语言豁免或个人资格。

## 原版发现的问题

默认端口已被占用时启动失败，本身是预期分支；README 已提供主服务换端口方法。下列两项才是已确认缺陷。

| 缺陷 | 原版实际复现 | 修复与复验目标 |
| --- | --- | --- |
| 换端口后 README 仍导向旧工作区 | 新克隆在替代端口运行，但文档的帮助与教程链接固定为 `http://127.0.0.1:4680/#guide` 和 `/#tutorial`；页面内的相对入口正确 | 文档改为打开启动输出的地址，再走当前站内帮助与教程；补充双终端及同一克隆目录步骤 |
| 博士示例不能按用户指定端口启动 | `npm run demo:phd -- --port 4696` 实际变为 `--port 4682 --port 4696`，仍报 4682 被占用；设置环境变量也无效 | 移除 npm 脚本固定端口，统一按显式参数、环境变量、分支默认值选择；显式参数可覆盖环境值 |

原版博士共 41 条检查，39 条通过、2 条失败。硕士路径也独立复现了文档的旧端口链接；没有因测试定位器写错、猜测教程名称或工具超时而增加产品缺陷数。

硕士原版八轮引导另有 73 条检查断言通过，文档缺陷单独记录；安装、备份与重启证据没有补造统一总数。范围收束前留下的一段原版生命周期模拟单列保存、不计本轮安装统计，也未作为修复版的配置快照。

技能安装本身并未失败：原版能安装全部 5 个文件，重复安装返回非零并保留已有文件。1.3.1 另外改善了安装输出，显示实际目录与加载方式；这项改进不被包装成“原来无法安装”的修复。

主代理另从 GitHub 克隆原版和修复版，在两个空的 Codex 用户目录中实际执行 `npm run install:skill`。本机 Codex CLI 为 `0.165.0-alpha.1.2`；使用其真实 app-server `skills/list`，两次均发现唯一 `grad-apply-onboarding`，作用域为用户、已启用、没有技能加载错误。修复版用户路径含中文和空格，也通过。

[当前官方技能文档](https://learn.chatgpt.com/docs/build-skills)列出了 `.agents/skills` 等目录；本机版本实际仍能发现本安装器使用的 `.codex/skills`。因此没有仅凭路径差异迁移或覆盖技能，也没有将该兼容目录判成失败。

两个测试 Agent 随后读取各自新安装的 SKILL 与 references，依其规则完成中文提问、模拟回答、提取说明和 CLI 写入。安装文件存在、客户端发现成功、Agent 执行流程是三项独立证据，不互相替代。本轮不宣称验证了新模型账号注册、所有客户端版本或通用自然语言理解准确率。
