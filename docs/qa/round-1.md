# GradAtlas 第一轮完整博士申请周期验收

测试日期：2026-10-27。场景：虚构申请者正在英国 Queen Mary University of London（QMUL）就读理论物理硕士，希望申请欧洲及美国博士。

**结果：本轮不通过完整周期验收。49 项主流程检查中 42 通过、5 缺陷、2 缺失；另有 8 项平台探针通过，共 57 项检查。** 基础展示、CLI 数据流、版本保护、实时同步、来源核验边界和备份恢复可用。完整申请周期的原生记录及引导尚未补齐；通用扩展表可以模拟承载，不等于已有完整申请管理功能。

本报告锁定第一轮基线。报告编写期间主工程已开始修复，不能把这里的旧版问题直接当作最新状态；修复需在第二轮重新验收。

原始复现脚本和日志保留在本地 `.runtime/`，不随公开源码发布。下列路径供本地核验；其他使用者可依据功能矩阵复测，并运行 `npm test`。

## 测试边界与证据

- 仅已知背景写入真实含义字段：博士方向、QMUL 理论物理硕士在读、欧洲和美国目标。没有编造 GPA、国籍、英语成绩、论文、科研项目、导师关系或真实招生资格。
- 程序流程使用三个明确虚构的目标：`eu-job`（欧洲岗位招聘）、`eu-supervisor`（欧洲导师制）、`us-program`（美国统一项目制）。2099 周期、目标名称、导师、金额、日期、回复和 offer 均为 QA 模拟值。
- `https://qa.invalid/…` 只作为虚构来源标识；网页正文由测试函数注入，没有把模拟日期写成真实招生事实。测试 `basis=official` 仅验证字段与页面口径。
- 没有发送真实邮件、联系导师、创建申请账号、支付费用、递交申请或访问无关私人目录。也没有修改正式 `.local/`、4680/4681/4682 实例或其数据。
- 通过 `createApp({ dir: 隔离目录 })` 启动系统分配的临时本机端口。使用真实 Edge、Playwright、原始 CLI 的字节副本、真实 Store 和实际页面交互，不以标题存在或自报测试通过代替操作。
- 每次 CLI apply 先 dry-run，再以当前 revision 写入。CLI 根目录固定到脚本位置，因此在 QA 目录中复制原脚本和库，避免触碰项目的正式 `.local/`。

复现命令（在项目根目录运行；Windows 沙盒中 Edge 需要允许本机浏览器进程）：

相关日期要分别表达：网申截止、推荐信到达、奖学金截止、offer 回复和注册可能同时存在。目前只有一个项目 `deadline`；个人任务日期不能冒充这些官方截止。建议新的周期记录保留可区分的里程碑，每项分别带来源、周期、时区与口径。单独使用 `录取` 作为原有项目阶段可以保留，不必为所有后段过程强行扩张成一个状态枚举。

这些增补源自本次实际周期，不把自动发送、真人资格推断、账户托管、全球规则数据库或无限智能规划列为发布阻断。通用扩展本身通过了测试，应继续保留；缺口是常见申请操作没有现成、可持续核对的数据流程。
